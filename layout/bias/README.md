# B1 bias generator layout (gf180mcuD, 3.3 V devices)

Schematic: `cells/bias/*.spice` (generated by `cells/bias/gen_cells.py`, rev C). LVS references are cut from those files by `refnet.py`.
Everything here is generated. Do not hand-edit the `.mag` files.

## Flow (from the repo root, Git Bash)

    scripts/eda.sh "cd layout/bias && bash build.sh"                       # every leaf: generate, magic DRC, LVS, KLayout DRC
    scripts/eda.sh "cd layout/bias && CELLS='idac_p rx_n4' bash build.sh"  # some cells (set CELLS inside the quotes)
    scripts/eda.sh "cd layout/bias && bash build.sh nogen"                 # re-verify only
    # ROUTE_QUICK=<iters> (inside the quotes): one negotiation schedule only, for placement experiments
    # PEX: BCELL=<cell> PEX=1 magic ... build.tcl  -> out/<cell>_pex.spice

| Step | File |
|---|---|
| Device library: `cellgen.py` calls `gf180mcu::{n,p}fet_03v3_draw` / `ppolyf_u_1k_draw` on demand (guard 0, no gate contacts) | `devices/*.mag` |
| Leaf placement + routing: receivers, `idac_n`, `idac_p` | `leafs.py` |
| Leaf placement + routing: `bias_rails`, `bias_master`, `bias_ladder` (rev C; the rev B `vref_string64`, `vdac6`, `bias_rangegen` generators are still in the file but no longer built) | `leafs2.py` |
| Leaf placement + routing (rev C): `bias_vi` (V-to-I + copies), `vdacr_el/_vr/_vc/_vt` (resistor-chain DACs); resistor lengths are read from `cells/bias/bias_vi.spice` | `leafs3.py` |
| Shared layout library (MOS rows with gate bars / heads, Metal1 rails, Metal2 drain busses, resistors, taps, rings, router driver, notch fill, writer, preview) | `cellgen.py` |
| Gridded PathFinder router, copied from `layout/slot/router.py` and generalised to Metal1–Metal3 | `router.py` |
| Assembly (rev C): `bias_b1` = column packer (`COLS_C`, entries may be rotated 90 deg or grouped side by side), Metal2/Metal3 router, block pins (digital top, analog west, ua[0] bottom, vdd/vss east); `python3 topgen.py place_c` prints the placement-only area. (`bias_vblk`, `bias_b1_n/_w` are the rev B studies.) | `topgen.py` |
| Magic: draw, DRC `drc(full)`, GDS, LVS netlist, optional PEX | `build.tcl` |
| netgen LVS (PDK setup) against `out/ref_<cell>.spice` | `out/<cell>_lvs_report.txt` |
| KLayout `gf180mcu.drc`: `variant=D`, `run_mode=flat`, `decks=all,-density` | `out/<cell>_klayout_drc.lyrdb`, `kl_count.py` |
| Previews | `out/preview_<cell>.png` |

Leaf conventions: origin at the lower-left corner; p-tap (vss) guard ring on the perimeter; Metal1 and Metal2 only (Metal3 is left free for the B1 top level); pins are labelled Metal2 pads (`out/geo_<cell>.json` lists pins and Metal1/Metal2 obstacles for a top-level router). Metal4/5 are never used.

DRC lessons (gf180mcuD, magic GDS output): keep an n-tap ≥ 1.0 µm from the n-well side edges and ≥ 0.6 µm from its top/bottom edges, otherwise magic's nplus generation leaves 0.35 µm ears (KLayout NP.1); one n-tap within 20 µm of every pfet (DF.13).
