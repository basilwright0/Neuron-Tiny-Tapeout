# C1 redesign handoff: more than 16 spike channels (step 1: analysis + plan, no RTL change)
Base fdcf2ad, branch r2-c1-spk. Paths are relative to the repo root.

## 1. Current architecture
- spk_in path: `input [15:0] spk_in` (rtl/neuron_ctrl.v:41) goes straight to the pins with no sync, no edge detect, no counters:
  `uo_out = spk_in[7:0]`, `uio_out = {out_mux?spk_in[15]:echo, out_mux?spk_in[14]:lif_spike, spk_in[13:8]}`, `uio_oe = 8'hFF` (neuron_ctrl.v:273-277).
  The only clocked use is the LIF event source (LIF_SRC=3 selects spk_in[0]): a toggle flop clocked by the source, then 2-FF sync (neuron_ctrl.v:220-239).
  Counting and timing run in the RP2040 PIO (docs/info.md:27). SDC treats spk_in[*] as async with a 4 ns input delay (rtl/librelane/constraints.sdc:13-14).
- OUT_MUX = MODE[2] (nc_regmap.vh:22). 0: uio[6] = digital-LIF spike, uio[7] = config echo. 1: uio[7:6] = ch15:14 (docs/regmap.md:34-35,96).
- PROBE 0x07: SEL[3:0], SUB[5:4], EN[6]. PROBE[7] has no storage (REG_USED 8'h7F, nc_regmap.vh:21,38; docs/regmap.md:108).
  The decode is a case on the 4-bit SEL giving 2-bit row/col (neuron_ctrl.v:164-192). AdEx (SEL 3) and D1 (SEL 13) are outside the array, decoded from ~p_arr & SEL[3] (:200-201).
- Address space: 5-bit ADDR, NREG=23, 0x00..0x16 (nc_regmap.vh:12-14). Free: addresses 0x17..0x1F (writes ignored, docs/regmap.md:46).
  Free bits: VDAC[7:6], PROBE[7], LIF_CTL[7:3], trim nibbles 1 and 9-13 (docs/regmap.md:108). MODE (0x08) is full.
- Write protocol: SCK=ui[0], DATA=ui[1], LOAD=ui[2]. A 13-bit frame {ADDR[4:0],DATA[7:0]} goes MSB first into a SCK-clocked shift register.
  `le[a] = LOAD & (addr==a)` opens one transparent latch bank (rtl/nc_cfg.v:3-11,29-38). No clk and no read-back. uio_in is unused (neuron_ctrl.v:282).
  nc_cfg hard-codes `le` as [22:0] (nc_cfg.v:21), so it must follow NREG.
- Reset: every latch is latrnq with async reset from the rst_n pin, so all bytes reset to 0. That means OUT_MUX=0 and probe off (neuron_ctrl.v:69-79; docs/regmap.md:18).

## 3. Readout options (N_SPK = 24..32; pins stay 8 uo + 8 uio)
(a) Byte-group bank select. New register OUT_BANK. Each output group gets a 2:1 mux between the base and the extended channels:
    uo[7:0] = ch0-7 | ch16-23, uio[5:0] = ch8-13 | ch24-29, uio[7:6] (when OUT_MUX=1) = ch14-15 | ch30-31.
    Pins: same. Reset: OUT_BANK=0 gives exactly the current mapping and regmap, so it is backward compatible.
    Simultaneity: 16 of N at once, and the host can mix groups (e.g. new ch16-23 together with ch8-15). Firmware: one write per bank switch, PIO unchanged.
    Area: about 16 mux2 + 2-3 latches + one address decode, roughly 300-450 um2 by the per-cell averages above. Tests: low.
(b) OUT_MUX extension only (uio[7:6] carry 2 extra channels in a new mode). This adds at most 2 channels, short of the 24 target.
    It also costs the echo / LIF observability. Rejected alone. It folds into (a) as the uio[7:6] group.
(c) Event-encoded: priority encoder to {valid, id[4:0]} on uo, with a per-channel capture latch/stretch so short async spikes are not lost.
    Same pins in a new mode, and reset can keep today's mapping. Simultaneity: one event per encode slot, so coincident spikes serialize or drop.
    The PIO decoder must be rewritten. Area: 24-32 capture flops + sync is about 1300-1800 um2 of sequential cells alone, which does not fit in 1352 um2 of fill.
    Combinational async encoding also glitches. Tests: high. Rejected.

## 4. Recommendation: (a), RTL parameter N_SPK=32, hardened at 32 (spare inputs tied low at top level)
RTL:
- rtl/nc_regmap.vh: NREG=24, A_OUT=5'h17. OUT[0] UO_BANK, OUT[1] UIO_BANK (uio[5:0]), OUT[2] HI_BANK (uio[7:6] when OUT_MUX=1). REG_USED 8'h07. Default 0.
  PROBE REG_USED 8'h7F -> 8'hFF, with PROBE[7] = SEL[4] (default 0).
- rtl/nc_cfg.v: le width parameterized as NREG (currently a literal [22:0]).
- rtl/neuron_ctrl.v: parameter N_SPK=32, `input [N_SPK-1:0] spk_in`, and output muxes as in (a).
  Probe: probe_sel = {PROBE[7], PROBE[3:0]}. With SEL[4]=0 the decode is unchanged, but sel_adex/sel_d1 must also AND ~SEL[4].
  SEL[4]=1: column-4 slots drive new probe_en_c[4] plus the existing probe_rsel (p_col widens to 3 bits). B1-bay neurons get new out-of-array lines probe_sel_b1[2:0] (like adex/d1).
  Exact SEL->slot table to follow the B1/col-5 floorplan.
- test/regmap.py (NREG 24, A_OUT, PROBE mask) and docs/regmap.md + docs/info.md (pinout table, OUT_BANK, SEL[4]).
cocotb (test/test_ctrl.py, run with test/run_tests.sh; tb.v widens spk to N_SPK):
- test_reset_defaults covers OUT=0 and PROBE[7]=0, with the 16-channel output identical to today.
- test_spike_pins_and_out_mux is extended to random 32-bit spk across all 8 OUT x OUT_MUX combinations.
- test_cfg_write_all/test_load_glitch_free cover addr 0x17. New: 0x18..0x1F still ignored, and a write to 0x17 does not disturb other bytes.
- test_probe_decode covers all SEL[4:0] x SUB. New: SEL[4]=0 is bit-identical to the old decode (regression table).
- LIF src 3 still uses spk_in[0].
Harden:
- rtl/librelane/mkpins.py:
  - spk_in[16..18] (B1 bay, tile x 80-129, y 12-116) go on the W edge bottom, local y about 2-12 (tile 153-163), which is a free region nearest the bay. The S west end is crowded (AdEx/D1).
  - Column-4 spikes and probe_en_c[4] go on W local y about 94-100 (tile 245-251, inside the column span 231-295). Free W slots remain between the existing spk/probe pins.
  - Spare spk_in[19..31] go on the W bottom and are tied low at top level.
  - Add probe_sel_b1[*] near the B1 spikes.
- Regenerate pin_order.cfg/config_fp.json and re-run run.sh. Check utilization (now 94%), setup/hold, DRC, antenna. Copy LEF/GDS/nl/spice/metrics to macros/neuron_ctrl.
- floorplan.py: SPIKE_CH gets new names 16..N-1, and the assertion at :288 changes to N unique channels. layout/top/config.py:123 range(16) -> N_SPK, plus the new probe nets.
Risks:
- Area: only 1352 um2 of fill at 94% utilization. If placement/routing fails, lower density pressure first (e.g. trim repair buffers, or put OUT_BANK in spare LIF_CTL[5:3] to skip the decode). Die growth is not possible because the tile is fixed.
- The uo path becomes a mux on an async signal, which can glitch only while OUT_BANK changes (firmware switches only between measurements).
- 16 more pins on W: route congestion near the array probe lines.
- Probe decode change could regress SEL 3/13 (covered by the regression test).
- Tied spare inputs must not be left floating at the top level (LVS).

## Step 2: RTL + cocotb (branch r2-c1-spk, on top of dd63c1c)
Lead decisions applied: option (a) sized for area. N_SPK = 24, uo bank only, PROBE[7] = SEL[4]. Not hardened yet.
RTL:
- rtl/nc_regmap.vh: NREG 23 -> 24. A_OUT = 0x17 with REG_USED 8'h01 (bit 0 OUT_BANK, [7:1] unstored). PROBE REG_USED 8'h7F -> 8'hFF.
- rtl/nc_cfg.v: non-ANSI header, so `le` is [NREG-1:0] (taken from nc_regmap.vh).
- rtl/neuron_ctrl.v:
  - parameter N_SPK = 24, spk_in[N_SPK-1:0], `uo_out = out_bank ? spk_in[23:16] : spk_in[7:0]`. uio is unchanged.
  - cfg_idx and the trim-storage test are bounded to 0x0F..0x16, so 0x17 is not treated as a trim byte.
  - The probe decode has a new SEL[4] branch: 16..18 drive new port probe_sel_bay[2:0] (PROBE_EN & SUB != 3). 22 / 23 drive new port probe_en_c4 plus probe_rsel[2] / [3]. Every other SEL selects nothing.
  - SEL[4] = 0 runs the old case unchanged. probe_sel_adex / probe_sel_d1 are also gated by ~SEL[4], and probe_en_c[3:0] by ~p_c4. SUB = 3 still selects REF for any SEL.
  - Existing ports are unchanged; there are 2 new latches and no new flops.
- src/project.v is the empty analog TT wrapper (the top is built in layout/top), so there is no RTL instantiation to update.
- Spare channels: spk_in[19..21] must be tied low at the top level (layout/top), see the open items.
- test/regmap.py:
  - NREG 24, A["OUT"], N_SPK.
  - probe(sel) maps SEL[4] to bit 7, and probe_fields() decodes a PROBE byte.
  - probe_lines() takes a 5-bit SEL and also returns (bay, c4). The new tables are SLOT_HI {22: (2,4), 23: (3,4)} and BAY_SEL {16,17,18}.
  - probe_lines_old() is the frozen fdcf2ad decoder.
- test/tb.v: 24-bit spk_in and the new ports.
- docs/regmap.md: pins row, the OUT row, PROBE[7] = SEL[4], the SEL 16..31 table, port table, latch count 154, unused addresses 0x18..0x1F.
- rtl/librelane/mkpins.py:
  - W bottom (local y 2.5-11.5): spk_in[16..18] interleaved with probe_sel_bay[0..2], then spares spk_in[19..21].
  - Free W slots: spk_in[22] at y 94.4, probe_en_c4 at y 96.6, spk_in[23] at y 100.0.
  - The spk_in count assert is now N_SPK. pin_order.cfg was NOT regenerated (see open items).
cocotb (test/test_ctrl.py):
- reset: uo = ch 7..0 with ch 23..16 set differently, and the new probe lines are 0.
- spike pins: 60 random 24-bit patterns for each OUT_BANK x OUT_MUX combination.
- New test_out_reg_and_unused: a write to 0x17 changes only bit 0, with the full image and outputs checked. All 256 values to each of 0x18..0x1F change nothing.
- probe: exhaustive SEL[4:0] x SUB x EN. For SEL < 16 the RTL equals probe_lines_old and the new lines stay 0. At most one target is enabled, the dummy slot is never selected, and every slot including (2,4) / (3,4) is reachable.
